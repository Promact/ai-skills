# Naming Conventions

- Names should say what a thing *is* or *does*, not how it's implemented
  (`activeUsers`, not `userList2`).
- Booleans read as a yes/no question: `isActive`, `hasPermission`,
  `canEdit`.
- Avoid abbreviations that aren't universally understood on the team; spell
  it out.
- Keep casing consistent with the stack's own convention (see the relevant
  `stacks/*.md` file) rather than mixing styles within a file.
- Match plurality to content: a collection is plural (`orders`), a single
  item is singular (`order`).
